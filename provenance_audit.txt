Runtime entry and active model
------------------------------

The application is launched by run_project.py. The backend is run with
backend as its working directory/PYTHONPATH, and backend/app is therefore the
runtime package imported as app.*. The root app/ directory contains ML
artifacts but is not the backend application package used by the launcher.

Current API registration is in backend/app/api/v1/router.py. It registers both
the legacy prediction router and the Geo V2 prediction router. Geo V2 requests
flow through prediction.py -> GeoV2PredictionService -> GEO_V2_MODEL_STORE ->
the configured checkpoint below.

Configured path from backend/app/core/config.py:
app/ml/artifacts/geo_v2/federated/robust-v2-hs1-prior2-unweighted-bw3-22-50r2e-seed42/best_model.pt

Resolved path verified by backend import:
backend/app/ml/artifacts/geo_v2/federated/robust-v2-hs1-prior2-unweighted-bw3-22-50r2e-seed42/best_model.pt

Runtime load verification:
- GeoV2ModelStore.maybe_reload() returned true.
- Model version: fedrouteai-geo-v2-robust-robust-v2-hs1-prior2-unweighted-bw3-22-50r2e-seed42-r45.
- Feature version: geo-v2-history_spatial_strong-23-v2.
- Ordered input feature count: 23.
- Network version: beeramguda-osm-20260506.
- The loader accepted the checkpoint and reported no error.
- The checkpoint includes state_dict, scaler, ordered feature names, label
  mapping, model dimensions, training configuration, and provenance metadata.

Feature-contract note:
runtime_inference.py has a stale module description saying "27-feature" and
FEATURE_VERSION = geo-v2-causal-120s-v2. The actual runtime builds vectors in
the loaded store's feature order. The current checkpoint's approved order is
the 22 history/current features plus neighbor_speed_delta, for 23 total. The
model loader and live import test agree on this 23-feature contract. Treat the
stale 27-feature text/version as documentation debt, not as evidence of a
second active model.

Active experiment and dataset provenance
----------------------------------------

Experiment directory:
backend/app/ml/artifacts/geo_v2/federated/robust-v2-hs1-prior2-unweighted-bw3-22-50r2e-seed42/

Evidence in provenance.json and manifest.json:
- Experiment id: robust-v2-hs1-prior2-unweighted-bw3-22-50r2e-seed42.
- Derived dataset: geo_v2_ml_v1_fixed_contract_v2.
- Untouched source dataset: geo_v2_ml_v1.
- Source dataset was preserved; the derived dataset contains train and
  validation splits and does not contain a derived test split.
- Training and validation paths use the history_spatial feature table.
- Test data was not accessed during training or checkpoint selection.
- Network version: beeramguda-osm-20260506.
- Training used eight geographic clients, unweighted NLL, 50 maximum rounds,
  two local epochs, and seed 42.
- Selected checkpoint: round 45.
- The final report records validation macro F1 0.3041565252 and full-test
  macro F1 0.3200260364, while documenting poor diversion and construction
  recall and explicitly rejecting unattended safety-critical use.

The fixed-contract dataset is therefore the direct training input for the
active checkpoint. data/geo_v2/fedrouteai_dataset_geo_v2_ml_v1 is the source
dataset and must not be treated as an unused duplicate. The base
data/geo_v2/fedrouteai_dataset_geo_v2 directory is an earlier/base Geo V2
dataset. data/raw/fedrouteai_dataset is the legacy/raw dataset referenced by
scripts/seed_db.py. data/raw/fedrouteai_dataset_v2 was empty during inspection
and has unknown provenance/value.

Audit conclusion
----------------
The current system has a traceable active model: the backend loads the robust
Geo V2 round-45 checkpoint, trained from the fixed-contract derived dataset,
which was generated from an untouched geo_v2_ml_v1 source dataset. The report
and research assets are separately identifiable. Historical, experimental,
duplicate, and scratch material remains present intentionally pending a human
decision; this file records provenance and does not authorize deletion.
