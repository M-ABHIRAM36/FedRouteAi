Why This Is a Real Fix, Not Cosmetic

The old system's Figure 3/4 finding was that 4 features were always zero regardless of whether data was actually missing — the model couldn't tell "genuinely absent" from "just how this endpoint works." observed_neighbor_count and history_observed_slots resolve this properly: the model sees a real, varying signal for data availability and can learn to weight predictions accordingly, instead of every request looking identically "incomplete."
